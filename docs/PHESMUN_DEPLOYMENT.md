## Target-identity guard

The 10 October smoke test showed that shell environment variables can silently override intended settings. Every
database-connected path therefore resolves the effective configuration and refuses to continue on a mismatch:

- **Build** (`next.config.ts`): a Supabase build pointing at DCMUN Development fails; a Production build must point at
  `EXPECTED_SUPABASE_REF` (default: the PHESMUN project).
- **Health probe** (`/api/health`): never contacts, and reports `down` for, a forbidden or unexpected project.
- **Operator scripts** (`scripts/*.mts`): `assertPhesmunTarget()` from `lib/platform/target-guard.ts` runs before any
  connection. Load and rehearsal tools are disabled outright.
- **SQL** (`supabase/phesmun/*.sql`): each script checks the marker comment on schema `supabase_migrations`
  (`conference-os-target=phesmun ref=gglltljhdpkfjnyjmnif`), which exists only in the PHESMUN database, and runs in one transaction.
